# 실험 일지

> 규칙: **Batch 2(Test)는 최종 모델을 확정하기 전까지 평가에 쓰지 않는다.** 모델 선택·튜닝은 Batch 1 (CV, Hold-out) 로만 한다.
> 결과가 나빠도 기록한다.

## 1. 실험 전 가설

1. **Test(Batch 2) 오차가 크게 나올 것으로 보는 이유** : Batch 2 셀의 77%(39셀 중 30셀)가 Batch 1 의 수명 범위(534~1,227) 밖(392~503)에 있어 외삽이 필요하고, 이 셀들은 같은 ΔQ 분산에서도 수명이 더 짧을 가능성이 있다(EDA Q1·Q3). Batch 1 에서 배운 관계가 그대로 맞지 않을 것이므로 **과대예측(편향 +)** 을 예상한다.

2. **피처를 더 넣으면 좋아지는가** : 유의미한 피처나 파생변수를 넣으면 좋아질 것으로 본다.
   - 유의미의 기준 : Batch 1 CV 와 Hold-out MAPE 가 함께 개선되고, 폴드·프로토콜이 바뀌어도 계수 부호가 유지될 때만 채택한다. (Test 결과로는 판단하지 않는다.)
   - EDA 에서 배치 간 부호가 일관된 피처는 `dq_logvar` 뿐이었다. `QD_slope`·`IR`·`Tavg` 는 배치마다 부호가 달라, 그대로 넣으면 Test 에서 오히려 나빠질 수 있다.
   - 파생변수 후보 : ΔQ(V) 곡선을 **전압 구간별로 나눈 분산** (단수명과 장수명의 차이가 큰 구간이 따로 있을 수 있다). Batch 1 CV 로 검증한다.

3. **9.1% 에 못 미칠 때 모델 문제인가, 데이터 문제인가**
   - Test 평가 전 : Train CV 와 Valid(Hold-out) 의 Gap 으로 과적합을 확인한다. Batch 1 안에서 수명이 짧은 셀을 빼고 학습한 뒤 그 셀을 평가해 "범위 밖 외삽" 문제를 미리 재현해 본다.
   - Test 평가 후 : Valid−Test Gap 이 크고, **모델을 바꿔도 Gap 이 그대로면 데이터(배치 이동) 문제**로 본다. 오차를 기존구조/신규구조 셀로 나눠서도 확인한다.
   - 데이터 변경의 범위 : 가능 = Batch 1 이상치 정리, 피처 정의 변경. **불가 = Test 셀을 골라 빼기, Batch 2 를 학습에 쓰기.**

### 결정 기록
- **Hold-out 처리** : Valid 21.2% 를 그대로 보고하고, 라벨 불확실 8셀을 뺀 결과를 함께 보고한다.
- 이유 : 결과를 보고 Hold-out 분할을 바꾸면 검증 숫자를 맞추는 셈이 되므로, 분할은 고정하고 원인을 설명한다.
- **XGBoost·LightGBM 의 추가** : 실행에 필요한 OpenMP 런타임(`libomp`)이 없어 처음 비교에서는 빠졌고, 설치한 뒤 같은 기준(Batch 1 CV, Hold-out)으로 다시 비교했다. 8개 모델 중 Train CV 가 가장 낮은 것은 여전히 핵심 피처의 선형 모델이라 최종 모델은 바뀌지 않는다.
- **앙상블** : 단순 평균 앙상블 4종을 Batch 1 에서 비교했지만 Train CV 가 모두 단일 선형 모델보다 높아(7.83~9.21 vs 7.40) 채택하지 않았다(`notebooks/03_modeling.ipynb` 8번 섹션).
- 알게 된 점 : Hold-out(11셀, 불확실 제외 시 8셀)은 표본이 작고 수명 범위가 좁아 모델 비교의 근거로 약하다. 모델 선택은 Train CV 와 함께 본다.

## 3. 최종 모델 확정 (Test 평가 전)

- 최종 모델 / 피처 : **핵심 피처 `dq_logvar` + Elastic Net** (`alpha=0.01`, `l1_ratio=0.5`, 스케일링·결측 대치는 학습 데이터로만 fit, 타깃은 `log10` 로 학습). 학습 데이터는 Batch 1 의 수명이 있는 46셀 전체로 다시 학습한다(하이퍼파라미터는 고정).
- 확정 근거 (Batch 1 의 어떤 결과를 봤나) : 사전에 정한 선택 기준(Train CV 최저, 복잡한 조합은 1%p 이상 낮아질 때만 채택)에 따라 선택했다. 핵심 피처의 선형 모델은 Train CV 7.2~7.4% 로 가장 낮았고, 어떤 추가 피처(구간 분산, 요약값, 충전)도 1%p 이상 개선하지 못했다. 단순한 모델이 같은 수준이라 해석도 쉬운 Elastic Net 을 택한다. 이 결정은 Batch 2 를 평가하기 전에 기록한다.
- Test(Batch 2) 에서 기대하는 결과와 그 이유 : 목표 9.1% 보다 오차가 크고, 과대예측(편향 +) 일 것으로 예상한다. 이유는 Batch 2 셀의 77% 가 Batch 1 의 수명 범위 밖이고(EDA Q1), 기존구조 셀이 같은 ΔQ 분산에서 더 일찍 수명이 끝나기 때문이다(가설 1).
- 평가 방식(미리 정함, 이후 아래 4번에 결과 기록) : Test 는 위 최종 모델 1개로 한 번 평가한다. 보조로 ① 라벨 불확실 8셀을 뺀 학습 결과(민감도), ② 비교군 모델(Gaussian Process, Gradient Boosting, Random Forest)의 Test 성능을 **참고용으로만** 함께 보고하고, 모델 선택에는 사용하지 않는다.

## 5. 사후 개선 (Test 평가 이후, 오차를 줄이는 시도)

> **주의** : 이 단계는 Batch 2·3 의 결과를 이미 본 뒤에 시작한다. 따라서 여기서 나오는 Test 값은 독립적인 검증이 아니며, 공식 결과(3·4번)를 대체하지 않는다. 선택은 **Batch 1 의 결과로만** 하고, 시도한 것은 모두 보고한다.

### 5-1. 시작 전 선언 (결과를 보기 전에 적음)
- **진단(4번 결과)** : 오차의 큰 부분은 ① 배치 간 관계의 이동(기존구조 셀) ② 학습 라벨 품질(라벨 불확실 8셀 제외 시 Batch 2 가 달라짐) 이다. ①은 Batch 1 만으로는 바로잡을 수 없다.
- **시도할 것 (Batch 1 안의 근거가 있는 것만)** :
  1. **학습 라벨 정리** : 기록 마지막 용량이 0.95 Ah 이상이라 수명 라벨을 검증할 수 없는 8셀을 학습에서 제외한다. (근거: Batch 1 의 데이터 품질. EDA 단계에서 "확인 필요"로 미리 표시한 셀이며, Test 점수와 무관하게 정의된다.)
  2. **라벨 이상치에 강한 회귀** : 정리한 학습 셀에서 Elastic Net(`alpha` 0.001 / 0.01 / 0.1), Ridge, Huber 회귀를 비교한다.
- **선택 규칙** : 정리한 Batch 1 학습 셀에서의 **Train CV MAPE 가 가장 낮은 모델**. Hold-out 은 표본이 작아 참고만 한다. Test 점수로는 고르지 않는다.
- **보고 방식** : 공식 결과(변경 전)와 사후 개선 결과를 나란히 표시하고, 개선분이 Test 결과를 본 뒤의 시도임을 명시한다.

## 6. 성능 개선 2차 — 배치 이동을 흉내 낸 Batch 1 검증으로 선택 (Test 평가 전)

> 5번의 Ridge(CV 선택)는 모델 간 차이가 0.1%p 이내라 의미가 작았다. 5번의 Test 셀은 아직 실행하지 않았으므로, 아래 6번의 선택으로 **대체**한다.

### 6-1. 시작 전 선언 (결과를 보기 전에 적음)
- **목적** : 모델 오차를 줄인다. 오차의 큰 원인은 "학습에서 보지 못한 수명 범위·조건"이므로, Batch 1 안에서 이를 흉내 낸 검증을 만들어 개선 방향을 고른다. Test(Batch 2·3)의 점수는 선택에 쓰지 않는다.
- **이동 흉내 검증** : 정리한 Batch 1(라벨 불확실 8셀 제외, 38셀)에서 ① 수명이 짧은 쪽 25% 셀, ② 긴 쪽 25% 셀을 각각 평가용으로 빼고, 같은 충전 프로토콜의 셀도 학습에서 뺀 뒤 나머지로 학습해 평가한다. 두 MAPE 의 평균을 점수로 쓴다.
- **시도할 조합 (24개)** : 피처 4가지(핵심 `dq_logvar` / + 구간별 ΔQ 분산 / + `QD_slope`·`IR`·`Tavg` / + `C1`·`switch`) x 모델 6가지(Ridge, Huber, Gaussian Process, Gradient Boosting, Elastic Net+GP 평균, Elastic Net+GP+GB 평균).
- **선택 규칙** : 이동 흉내 검증 점수가 가장 낮은 조합. 단, 기준(핵심 피처 + Ridge)보다 **1%p 이상 낮을 때만** 교체한다. 그렇지 않으면 기준을 유지한다.
- **보고 방식** : 24개 전부 표로 보고하고, 확정 후 Test(Batch 2·3)는 한 번만 평가한다. 이 Test 값도 5번과 같이 "사후 개선"이며 공식 결과를 대체하지 않는다.

### 5-3. (사후 기록) 5-2 모델(라벨 정리 + Ridge, 핵심 피처만)의 Test 결과
- 5-2 의 Test 셀은 6-2 확정을 기록한 **뒤에**, 노트북을 다시 열기 전의 이전 버전에서 실행되었다. 결과는 아래와 같다 (`results/model_performance_post_hoc.csv` 의 이전 실행분).

| 구분 | 공식 결과 (변경 전) | 5-2 모델 (라벨 정리 + Ridge) |
|---|---|---|
| Train (Batch 1 CV) | 7.40 | 8.07 (정리 후 30셀) |
| Valid (Batch 1 Hold-out) | 21.20 | 10.78 (정리 후 8셀) |
| Test (Batch 2) | 38.32 | **29.16** |
| Test (Batch 3) | 13.98 | **12.18** |

- 개선(38.32 → 29.16)의 대부분은 **라벨 불확실 8셀을 학습에서 정리한 효과**이다. 같은 정리를 Elastic Net 에 적용했을 때 이미 30.31 이었고, Ridge 로 바꾼 효과는 약 1%p 이다.
- 이 결과를 본 뒤의 취급 규칙(미리 적어 둠) : 사후 개선의 **대표 모델은 6-2 에서 먼저 확정한 모델**(핵심 + 충전 + Ridge)로 하고, 5-2 모델의 결과는 **참고로 병기**한다. 두 결과 중 Test 가 더 좋은 쪽을 고르지 않는다.

### 6-3. 6-2 모델(핵심 + 충전 + Ridge)의 Test 결과 — 오히려 나빠짐
- 5-3 의 규칙대로 **사후 개선의 대표 모델은 6-2 모델**이며, 결과는 아래와 같다 (5-2 모델의 결과는 참고).

| 구분 | 공식 결과 (변경 전) | 5-2 모델 (라벨 정리 + Ridge) | **6-2 모델 (라벨 정리 + 핵심·충전 + Ridge)** |
|---|---|---|---|
| Train (Batch 1 CV, 정리 후) | 7.40 | 8.07 | 8.69 |
| Valid (Batch 1 Hold-out, 정리 후) | 21.20 | 10.78 | 10.51 |
| Test (Batch 2) | 38.32 | 29.16 | **43.92** |
| Test (Batch 3) | 13.98 | 12.18 | **16.24** |
| Gap (Target-Test) [Batch 2] | +29.22 | +20.06 | **+34.82** |

- **해석** : 이동 흉내 검증에서 12.39%(기준 14.20%)로 좋아 보였던 6-2 모델이 실제 Test 에서는 공식 결과보다도 나빠졌다(Batch 2 38.32 → 43.92, Batch 3 13.98 → 16.24).
  - 충전 피처(`C1`, `switch`)는 EDA 에서 배치마다 효과가 달랐다. Batch 1 의 충전 프로토콜 안에서 배운 관계가 Batch 2·3 의 프로토콜(평균 C-rate 가 4.8C 로 고정)에는 맞지 않는 것으로 보인다.
  - **한 배치 안에서 이동을 흉내 낸 검증도 실제 배치 이동을 반영하지 못했다.** 이동 흉내 검증이 좋아진 것이 Test 의 개선으로 이어지지 않았다. 검증이 쉬운 방향(충전 피처가 같은 배치 안의 프로토콜 차이를 잘 설명)으로 모델이 맞춰졌기 때문이다.
- **취급** : 6-2 의 규칙(선언한 대표 모델)을 유지하므로, Test 가 더 좋은 5-2 모델로 바꾸지 않는다. 사후 개선 시도는 여기서 **종료**한다(Test 를 보며 더 고치는 것은 평가의 독립성을 더 해치므로).
- **정리** : 공식 결과는 38.32% 로 그대로이다. 사후 시도에서 확인된 것은 ① **라벨 불확실 셀 정리는 도움이 된다**(38.32 → 29~30%) ② **충전 피처 추가는 배치를 넘어 일반화되지 않는다** ③ **한 배치 안의 검증으로는 배치 간 일반화를 고르기 어렵다** 이다.
